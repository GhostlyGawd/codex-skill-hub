## Blocking finding

### T6 — The positive non-skill case is not genuine

Task 4.8 requires a genuine non-skill fixture to pass. Its evidence cites N10. N10 calls `make_valid_repo`, which creates:

- `skills/alpha/SKILL.md`.
- `evaluations/alpha/cases.md` and `results.md`.
- Specification links to that skill package and evaluation.
- A task output at `skills/alpha/SKILL.md`.

N10 then deletes these files and links before it runs `--all`. Thus, the test is a completed skill with its identity removed from the current tree. It is not work that was non-skill from the start. This setup is the absence-based classification pattern identified by V4.

Effect: task 4.8 can meet its current verification text without proving that the validator accepts a real completed non-skill work item. The negative base/head regression protects a known completed base skill, but the positive test does not prove the other side of the classification boundary.

Required correction:

1. Create a separate non-skill fixture from the start. It must use non-skill outputs, tasks, specification text, and implementation evidence. It must never create a skill package, skill evaluation directory, skill links, or a skill output path.
2. Run this fixture with `--all` and require exit 0.
3. Keep the existing base/head completed-skill deletion regression and require its stable failure ID.
4. Update task 4.8 to name both distinct fixtures and their expected results.
5. Issue task-list version 0.5 and validate it in report sequence 07. Because sequence 06 failed, move the planned implementation revalidation to sequence 08 or later.
